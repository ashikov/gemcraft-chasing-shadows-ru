# Два представления каталога локализации

Полные оригиналы, кандидаты, символы ABC и ручная работа хранятся **только локально**
в исключённом из Git `local/extraction/`. Перевод ограничен меню настроек.
`translations/ru.json` сохраняет прежний формат и единственный проверенный пример.
Проверенный рецепт заголовка сохранён; дополнительные адресные переводы сборщик
читает из локального workspace по отдельному плану этапа 3. Публичный пример
не управляет сборкой. Наличие каталогов не разрешает установку или запуск игры.

## Воспроизводимое извлечение

Python 3.11+, стандартная библиотека; окружение и dev-проверки описаны в README.
Используйте собственный оригинальный SWF с поддерживаемым SHA-256. При установленном
прототипе нужен оригинальный backup, а не файл из каталога игры. Все команды ниже
читают оригинал; запись идёт только в новые файлы. Игру они не запускают.

```sh
mkdir -p local/extraction
python extract_strings.py /path/to/original/gc-cs-steam.swf \
  --original-sha256 c8eadc03a7e607086998695f7696ec22dd90d7b7859e3d10cdfabf40fc7bbad5 \
  --inventory --output local/extraction/original-strings.json \
  --report local/extraction/inventory-report.json
python localization_workspace.py init local/extraction/original-strings.json \
  --seed translations/ru.json --output local/extraction/translation-workspace.json
python localization_workspace.py validate local/extraction/translation-workspace.json \
  --inventory local/extraction/original-strings.json
```

`--inventory` требует именно поддерживаемый SHA; модифицированный или неизвестный
SWF отклоняется. Старый CLI `--static-id 3016 --output output/selected-static.json`
сохранён для выборочного верхнеуровневого экспорта; он не заменяет инвентаризацию.
Все выходы создаются эксклюзивно: для повторного запуска выберите новые имена.
Сериализация детерминирована, без времени генерации. ID стабильны для неизменного
оригинала; совместимость адресов между версиями не обещается.

## Машинный каталог и ручная работа

`original-strings.json` — машинный снимок: `schema_version: 1`, `game_sha256`,
`entries`, `placements`, `coverage`. Он включает технические строки отдельно по
`classification`, чтобы переводчик мог фильтровать их без потери свидетельств.
Полные кодовые дампы, ABC и контуры глифов в него не экспортируются.

Запись содержит `id`, `category`, точный `source`, его UTF-8 `source_sha256`,
`location`, `classification`, `context`, `context_confidence`, `translation`
и `mandatory_placeholders`. Дополнительные поля зависят от структуры:

- `static.<character_id>`: DefineText/2, bounds, matrix, список font IDs,
  отдельные `text_records` с исходным текстом, явными изменениями формата,
  индексами глифов и advances. Удобный `source` объединяет глифы без придуманных
  переносов; исходные границы и координаты сохраняются в records.
- `edit.<character_id>`: DefineEditText, точный InitialText, включая HTML,
  flags, bounds, VariableName, font/fontClass, высота, RGBA, maxLength и layout.
  Пустой компонент сохраняется как отдельная запись `unknown`; его динамический
  текст из самого тега не восстановить.
- `abc.<tag_path>.<method_index>.<code_offset>`: использование `pushstring`,
  индекс строки, адрес инструкции, метод и доступные class/trait labels.
  Неиспользованные декодером непустые элементы pool получают отдельные
  `abc.<tag_path>.pool.<index>`; это не подтверждённые надписи.

`tag_path` — индексы тегов в последовательности и вложенных DefineSprite;
`sprite_path` — Character IDs владельцев. `placements` содержит найденные
character-bearing PlaceObject/2/3 с depth и номером кадра, начиная с нуля.
Это граф ссылок, а не симуляция timeline: удаления, наследование transform,
достижимость спрайтов и видимость не реконструируются.

Классификация не равна статусу готовности перевода:

- `confirmed`: текст непосредственно закодирован в текстовом SWF-компоненте
  либо контекст подтверждён вручную. Наличие определения не доказывает видимость.
- `probable`: текстовый кандидат по использованию/форме, включая литералы,
  присваиваемые `.text`/`.htmlText` при неизвестном типе получателя.
- `technical`: строка связана с программным символом, именем или метаданными
  и не имеет установленного текстового назначения. Программные ключи без такой
  связи могут остаться `unknown`: эвристика не доказывает их переводимость.
- `unknown`: назначение не установлено, включая пустые динамические поля.

`context_confidence` (`confirmed`, `inferred`, `unknown`) оценивает контекст,
а не правильность русского текста. Предположения сохраняются как предположения.
Эвристики ABC не являются декомпилятором или доказательством назначения строки.
HTML-фрагменты в ABC остаются `category: actionscript` с `content_type:
html_fragment`; баланс разметки отдельного фрагмента не требуется.

`translation-workspace.json` — рабочее двуязычное представление. Технические
записи не превращаются в задачи перевода. Машинные поля доступны рядом с ручными
`translation`, `context`, `notes`, `status`, `mandatory_placeholders`,
`classification`, `context_confidence`. Статусы: `untranslated`, `draft`,
`verified`, `needs_review`. Неизвестный перевод — `null`; намеренно пустой — `""`.
Исходник не нормализуется. Одинаковые фразы по разным адресам остаются отдельными.
Существующий seed переносится только после точной сверки оригинала, SHA и
совместимых адресов, а не по совпадению английской фразы.

Правьте ручные поля структурированным редактором JSON. Не меняйте `id`, `source`,
`source_sha256`, `location` или `game_sha256` ради принятия перевода. Для
терминологических решений используйте ручные `notes` и локальный глоссарий;
отслеживаемый `translations/glossary.json` не расширяйте массовым текстом.

## Повторное извлечение и конфликты

Сначала извлеките новый машинный снимок в другой файл, например
`local/extraction/original-strings-next.json`, затем:

```sh
python localization_workspace.py reconcile local/extraction/translation-workspace.json \
  local/extraction/original-strings-next.json \
  --output local/extraction/translation-workspace-next.json
python localization_workspace.py validate local/extraction/translation-workspace-next.json \
  --inventory local/extraction/original-strings-next.json
```

При неизменных ID, category, source, SHA, location и game SHA ручные поля
сохраняются. Изменение версии, текста или адреса сохраняет полный прежний снимок
и новый снимок в `conflicts`, устанавливает `needs_review` и убирает устаревший
перевод из активной записи (`null`). Удалённая или ставшая технической запись
также архивируется. Ранее нерешённые конфликты остаются при следующей сверке.
Старые файлы не перезаписываются. Сравните `old`/`new`, заново проверьте контекст
и перевод; явное разрешение конфликта выполняется в новом рабочем файле после
сохранения прежнего снимка. Не присваивайте `verified` автоматически.

## Валидация и минимальное представление

Старый `translation_catalog.py translations/ru.json` сохранён без изменения
контрактов. Для обычного каталога `--allow-missing` допускает `null`; проверяются
повторные JSON-ключи/IDs, SHA исходника, Unicode и заявленные обязательные токены.
Для полного workspace используйте `localization_workspace.py validate`:
он также проверяет статусы, классификацию, конфликты и связь с машинным снимком.
Для целого `category: html` проверяется баланс тегов; это не проверка Flash HTML,
атрибутов, шрифтов, переносов или отображения. Для ABC-фрагментов баланс отключён.

```sh
python localization_workspace.py minimal local/extraction/translation-workspace.json \
  --allowlist translations/ru.json --output local/extraction/minimal.json
python localization_workspace.py validate-minimal local/extraction/minimal.json \
  --workspace local/extraction/translation-workspace.json \
  --allowlist translations/ru.json
```

Минимальная совместимая проекция — `schema_version: 1`, `game_sha256`, `entries`
с `id`, `category`, числовыми `location`, `source_sha256`, `translation`.
Нет `source`, контекста, class/method labels, VariableName или fontClass.
Она предназначена для будущей адресной сборки, которую этот этап не реализует.
Экспорт допускает только уже проверенную запись из явно указанного allowlist
с тем же исходником, SHA, адресом и переводом; новые переводы вызывают отказ,
непереведённые массовые IDs не экспортируются. Сейчас allowlist — существующий
`translations/ru.json`. Это технический ограничитель, а не разрешение на
распространение нового allowlist. Рабочий перевод имеет один источник истины в
workspace; минимальный файл всегда пересоздаётся и проверяется по нему.

## Охват и границы

Рекурсивно разбираются DefineSprite, DefineText (11), DefineText2 (33),
DefineFont2/3 (48/75), DefineEditText (37), DoABC (82 и старый raw-ABC 72).
ABC поддерживает структуру версии 46.16, pool, namespaces, multinames,
methods, traits, classes/scripts, bodies и ограниченный набор стандартных
AVM2-инструкций. Неизвестный opcode останавливает декодирование своего body;
pool сохраняется, а coverage явно становится partial. Повреждённая структура
или неподдерживаемая версия ABC дают ошибку, а не пустой успешный результат.

Не реализованы универсальный dataflow, доказательство типа получателя,
восстановление всех динамических конкатенаций, локализация символов/ключей,
переписывание байткода, AS1/2, DefineFont/FontInfo, DefineFont4 и внешние ресурсы.
Растровый/векторный текст вне текстовых тегов не распознаётся. Не все значения
по одному `pushstring` — надписи; строковые defaults и неразобранные использования
остаются pool-кандидатами. Полнота перечисления тегов/pool не означает полноту
пользовательских текстов. Runtime-анализ не выполнялся.

Правила файлов и публикации: полный каталог, любые новые массовые переводы,
контексты с оригиналами, labels, дампы, шрифты и ресурсы остаются локальными.
В Git идут собственные инструменты, синтетические тесты, документация,
существующий пример и проверенные агрегаты [инвентаризации](string-inventory.md).
Не добавляйте массовую проекцию IDs/метаданных без отдельной оценки содержимого.
Удаление английского текста не решает вопрос прав на производный перевод;
см. [правовой статус](legal.md).

Форматы проверены по [Adobe SWF19](https://open-flash.github.io/mirrors/swf-spec-19.pdf),
[Adobe AVM2 opcode table](https://github.com/adobe-flash/avmplus/blob/65a05927767f3735db37823eebf7d743531f5d37/core/opcodes.tbl)
и upstream [Ruffle reader](https://github.com/ruffle-rs/ruffle/blob/2372a4e148a67d68efd796f4477b3cddd4f880cd/swf/src/read.rs).
В учтённых errata FontHeight присутствует при HasFont или HasFontClass,
Indent знаковый; PlaceObject3 HasImage добавляет ClassName только при отсутствии
HasCharacter. Технические ссылки не содержат материалов игры.

## Адресное применение локального меню (этап 3)

`addressed_localization.py` читает существующий рабочий каталог без изменения
его формата. Новый публичный каталог переводов не создаётся. Локальный план
содержит `schema_version: 1`, `game_sha256`, уникальные `entry_ids`, список
`fonts` и `layouts` по ID. Для каждого выбранного ABC-адреса задаются `font_id`,
`height` и `max_width` в twips, `wrap`; опционально `max_height`, `max_lines` и
`dynamic_suffix_budget` для добавляемого числа/суффикса. `unconfirmed` хранит ID
обработчиков с неподтверждённой достижимостью. План задаёт только выбор и ограничения,
сами source/translation остаются в существующем workspace.

`alternate_font_ids` — опциональный список других выбранных начертаний, которые
может использовать поле после присваивания текста. Сборка проверяет наличие всех
глифов и те же ограничения геометрии отдельно для каждого начертания; результат
добавляется в `layout_checks[ID].alternate_faces`. Это явное требование локального
плана, а не симуляция выбора шрифта Flash. Первоначальный HTML `<b>` не доказывает
формат позднее присвоенного plain text.

До редактирования workspace сохраните отдельный побайтово проверенный снимок.
Не перезаписывайте ручные переводы и заметки. Выбранные задачи должны иметь
подтверждённые контекст и классификацию, непустой тип translation (намеренно пустая
строка допустима), status `draft` либо `verified` и не иметь конфликтов. `draft`
пригоден для офлайн кандидата и не означает визуальную проверку.

Вся база сверяется со свежим извлечением из хешированного оригинала: ID, category,
source, source SHA и location. Выбранное использование привязано к DoABC,
method index, code offset, pool index и ABC byte offset. `abc_patch.py` добавляет
отдельные литералы в конец пула и меняет только выбранные pushstring-операнды.
Исходные pool entries, multinames, ключи и технические символы остаются побайтовыми.
Ширина операнда сохраняется, включая допустимое неминимальное u30; при нехватке
ширины сборка прекращается. Длины методов, переходы, исключения и debug-инструкции
не перемещаются. Сборка детерминирована и повторно разбирается.

Сохраняются обязательные плейсхолдеры и количество управляющих символов.
Этот механизм поддерживает plain text через top-level DoABC и известный заголовок.
HTML-фрагменты отклоняются: проверка баланса тегов сама по себе не доказывает
отображение Flash HTML. Остальные статические тексты не переписываются.

В подтверждённом меню найдены: один статический заголовок, восемь кнопок/текстов
подтверждения, четыре заголовка разделов, два предупреждения, 57 надписей
параметров и 69 фрагментов подсказок. Числа создаются динамически; три литерала
процента сохраняются. Boolean-переключатели используют кадры без текстовых ON/OFF.
Дополнительно покрыто уведомление обработчика сброса обучения; его привязка
к доступному элементу не найдена, поэтому достижимость не заявляется.

Местный перечень с ID, исходниками, переводами, адресами и уверенностью находится
в `local/extraction/options-menu-inventory.json`; это приватные игровые данные.
Первый разрешённый запуск выявил пустые подписи при работающих заголовке и
подсказках. Во втором запуске после расширения regular font1 подписи появились
во всех четырёх разделах; проверены подсказки с текущими значениями 80%, 4 с и
88%, прокрутка и кнопка выхода из настроек. Пользователь заметил неверную форму «п» и «ю»
и неудовлетворительную «б». Рецепты исправлены локально; новый кандидат имеет
статус **READY FOR RUNTIME VERIFICATION**. Общий статус — **PARTIAL** до проверки
новых форм, остальных значений и состояний, боевых подтверждений и достижимости
дополнительного уведомления. Каждый новый запуск требует отдельного разрешения.

Для дополнительной офлайн интеграции задайте `GEMCRAFT_ORIGINAL`,
`GEMCRAFT_OPTIONS_WORKSPACE`, `GEMCRAFT_OPTIONS_PLAN`, `GEMCRAFT_OPTIONS_RECIPES`
и выполните `python -m pytest -q -m local`. Тест собирает кандидат дважды,
сверяет воспроизводимость и отказ при повреждении, применяет/восстанавливает
только временную копию и проверяет её штатным verifier. Отсутствующие локальные
данные дают skip, который не является подтверждением интеграции.

При обновлении установки сохраните старый кандидат и неизменяемый оригинальный
backup, проверьте оба манифеста и все SHA. Сначала проверьте последовательность
старый патч → original → новый патч → original → старый патч на временной копии.
Рабочий переход использует restore старого манифеста, затем apply нового кандидата;
откат к предыдущему прототипу — restore нового манифеста, затем apply сохранённого
старого кандидата. Не редактируйте манифесты вручную. Не запускайте игру этой
последовательностью. Для каждого отдельного запуска требуется разрешение.
